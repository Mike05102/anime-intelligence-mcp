# GPDの自律成長と検証

GPDは、検証済みカタログ、販売業者の配送・在庫情報、買い手の引き渡し依頼、照合済みの注文と仲介手数料を使って、商品探索の裁量枠を調整する。全24カテゴリーの定期巡回枠と外部照会上限は維持する。

| 工程 | 接続と検証 |
|---|---|
| 販売業者 | [承認済みの定期巡回](GPD_MERCHANT_COVERAGE_TICK.md) は最大32のソースを対象に、1時間最大4件の取得を行う。公開前の承認と [フィード登録](GPD_MERCHANT_OFFER_FEED.md) は既存契約を使う。 |
| AIエージェント | [発見文書と買い手認証](GPD_AGENT_ONBOARDING.md)、MCPの `merchant_directory` と `merchant_gtin_search` を使い、販売業者、配送先、希望数量、商品状態を照会できる。 |
| 取引の証拠 | [署名付き注文・決済の照合](GPD_RECONCILIATION.md) で、過去7日以内に成立した外部注文、締結済み契約、確定入金が一致したものだけを採用する。買い手の引き渡しに保存した検証済みカタログのカテゴリーを使う。 |
| 商品探索への反映 | 取引・顧客IDや金額を渡さず、カテゴリ別の確認済み注文・照合済み請求件数を上限10で保存する。DB内の最新かつ24時間以内の本番区分スナップショットだけを使用する。裁量枠への最大加点は0.15。 |

## 照合済み集計の取り込み

管理下の非公開環境で、独立した発行者の署名済みバンドル・信頼台帳・期待するスナップショットIDを用意する。既定のコマンドはプレビュー。

```sh
node scripts/gpd33_apply_growth_evidence.mjs <署名済みバンドル> <信頼台帳> <スナップショットUUID>
```

承認済みDBに適用できる段階で、`PGHOST`、`PGDATABASE`、`PGUSER`、`PGSSLMODE=verify-full` と既存の認証を非公開実行環境へ設定する。`GPD_GROWTH_APPLY=1` と `--apply` を両方指定した場合に限り、本番区分の署名済み集計をサービス権限のRPCに送る。テスト区分のデータはプレビューに限る。DBは同じスナップショットの再送を重複計上せず、環境・内容の異なる再送を拒否する。実際の注文台帳・決済、接続先、権限、無料枠を確認したあとで `GPD_RECONCILED_GROWTH_SIGNALS=1` を設定する。設定は既定で無効。買い手依頼の加点は既存の `GPD_BUYER_GROWTH_SIGNALS` で個別に管理する。

現在の検証はモック、検証用の署名鍵、隔離PostgreSQLを使う。実際の販売業者・外部エージェント・三者間の取引・入金実績は未確認。次は条件が確認できた提携先の定期接続、台帳発行者の照合、少数案件の実運用と探索配分への効果測定。
