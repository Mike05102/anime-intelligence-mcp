# GPD 実装評価と取引・収益ロードマップ

基準日 2026-11-25。対象はv33.0のリポジトリ実装。事業目的は [GPD事業目的と恒久開発指針](GPD_DEVELOPMENT_CHARTER.md) に従う。

**判定**　実装済みはコードとテストの証拠がある範囲。部分実装は対象範囲や業務フローに欠けがある状態。未実装は成立に必要な機能を確認できていない状態。本番検証済みは本番で観測した具体的な機能に限定し、v33.0での稼働証拠と従来版の証拠を区別する。

| 必須機能 | v33.0の判定と残る仕事 | 本番検証の範囲 |
|---|---|---|
| 1. エージェントからの購買要求 | **実装済み**。MCPと購買判断APIで要求を処理。継続利用を追うエージェント識別は未実装。 | 従来版の公開稼働。v33.0の実エージェント調達は未検証。 |
| 2. 世界の商品収集・更新 | **部分実装**。既存情報源、食品データ、自律探索と再開。メーカー、卸、地域別の情報源は不足。 | 従来版の探索ログ。v33.0の長期稼働と登録速度は未検証。 |
| 3. 商品特定・重複排除 | **部分実装**。構造化GTIN、メーカー＋MPN、バリエーションの検証とDB競合対策。全商品・全提供元の正確性監査は未実施。 | 本番の全件照合は未検証。 |
| 4. 購買判断 | **部分実装**。価格・在庫・配送などの根拠と、欠損時の見送り判定。品質、納期、地域別の条件・信頼情報の網羅性は不足。 | v33.0の実購買結果に照らした精度は未検証。 |
| 5. 推薦から購入・商談 | **部分実装**。推薦、販売先URL、購入意向の記録。管理者起点の引き渡しと販売業者認証付きの受理・注文・取消報告を実装。外部の注文台帳との照合は未実装。 | 引き渡しから注文成立までの通し検証は未確認。 |
| 6. MCP・API・x402 | **実装済み**。MCP初期化・ツール一覧、HTTP 402と既存有料APIをテスト。 | 従来版の公開稼働。v33.0の本番切替前。 |
| 7. Solana USDC・収益 | **部分実装**。x402で情報提供料の検証・決済と記録。入金との照合、返金、仲介手数料と利益管理は不足。 | 従来版に決済記録あり。外部顧客・純収益・仲介手数料の照合は未確認。 |
| 8. Merchant機能 | **部分実装**。登録・認証、オファー更新、検索とフィード。自社への引き渡しの取得と結果報告を試験実装。一般商品のカバー範囲、外部注文システムとの自動連携は不足。 | 実販売業者による登録から収益までの検証は未確認。 |
| 9. 自律成長 | **部分実装**。商品探索・再検証・更新。取引成立や収益を基に販売業者・需要を拡大するループは不足。 | 従来版の商品探索を観測。v33.0の継続成長は未検証。 |
| 10. 多言語・多通貨・多地域・多産業 | **部分実装**。言語と地域の正規化、複数分野、通貨付き価格。地域別税・配送、FX・支払い対応の確認が必要。 | 実取引での地域横断対応は未検証。 |
| 11. 監視・自己診断・容量 | **部分実装**。診断、ジョブ再開、ログ集計、DB容量制御・転送削減。課金期間の利用量と業務SLOの取り込み、物理容量を常時保つ運用は不足。 | 本番Supabaseのログ集計と保守ジョブを確認。v33.0の本番負荷は未検証。 |
| 12. アニメ商品・産業部品 | **実装済み**。専門ルートと内蔵Parts Collectorの回帰テストあり。今後も固有の証拠・比較項目を維持する。 | 従来版の専門サービス稼働を確認。v33.0での本番回帰は未検証。 |

実装根拠は [Worker](../releases/GPD33_0_COMPLETE_WORKER.js)、[移行SQL](../supabase/migrations/)、[既存のリリース検証](../reports/gpd33-release-verification.md)。HTTP稼働、決済イベント、購入意向、実入金、商品取引成立は別々の証拠を必要とする。

## 実装順序と完了の判断

| 段階 | 優先する仕事 | 完了の証拠 |
|---|---|---|
| 0. 安定化と収益の測定 | 本番DBの整理と物理回収を続ける。管理APIで、購買判断・引き渡しイベント・決済証跡の集計を分ける。 | 現行機能の合格と保護対象の照合。DB・転送・稼働条件がそろってv33.0へ切替。稼働後の測定値を確認。 |
| 1. 最初の外部有料購買判断 | 既存専門アダプターから購入可能な案件を選び、実エージェントと販売業者で通し検証。決済記録とファシリテーター・ウォレットの入金を照合。 | テストを除く1件以上の入金、判断の提供、販売先への追跡可能な引き渡し。 |
| 2. 実取引の成立確認 | 販売業者に渡す参照ID、受理・拒否・注文・取消の通知を設計する。販売側の署名検証、冪等性、監査、返金・手数料照合を先に固める。 | 買い手の同意、販売業者の受理、外部取引成立の証跡と仲介手数料の照合。 |
| 3. 販売業者・需要の拡大 | 再利用可能なMerchantフィード連携、地域別の配送・通貨、照合品質の監査、利用エージェントの計測を広げる。 | 稼働する販売業者・購入可能な商品・利用エージェント・成立件数の増加を継続測定。 |
| 4. 自律拡張 | 成立・再購入・収益と運用原価を探索配分に反映し、地域・産業・情報源を段階的に拡張。 | 収益と品質の改善を、容量・転送量・費用の実績と併せて確認。 |

段階0の最初の変更として、管理者専用の `GET /admin/business-outcomes` を実装した。過去30日間の既存イベントをDB内で集計し、取引ハッシュとネットワークの組で決済記録を重複排除する。金額に矛盾する記録は収益合計から外す。集計にはテストの記録も含まれる。照合済み外部収益、商品取引の成立、他の未計測指標は `null` で返す。既存のMCP、API、x402の公開契約は維持する。

試験実装の契約は [販売業者への引き渡し](MERCHANT_HANDOFFS.md) を参照する。中断後の再開手順と次の仕事は [継続開発と引き継ぎ](GPD_CONTINUITY.md) に記録する。
