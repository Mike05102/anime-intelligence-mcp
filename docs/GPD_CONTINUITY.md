# GPD 継続開発と引き継ぎ

基準日 2026-11-25。設計判断は [恒久開発指針](GPD_DEVELOPMENT_CHARTER.md)、各機能の評価と完了条件は [ロードマップ](GPD_ROADMAP.md) に従う。セッションや自動タスクを再開したら、最初に本ファイル、GitHubの最新コミットと検証結果、現在の本番状態を確認する。

## 現在の開発段階

- v33.0の分析用管理APIに、販売業者が認証して報告した受理・注文・取消の集計を追加した。実装とローカル検証は [販売業者への引き渡し](MERCHANT_HANDOFFS.md) を参照する。
- GitHub上の統合開発と本番の整理は並行で進める。本番から隔離したPostgreSQL、外部サービスのモック、GitHub Actionsを使う。運用者が発行した期限付きトークンで、買い手が引き渡しの最新状態を確認できる経路を追加し、WorkerとPostgreSQLを通したテストで照合済み実績との区別を確認した。
- 部品の販売業者検索に、メーカーと型番が一致し、検証済み販売業者が対象国への配送と在庫を明示している引き渡し候補を追加した。検索から引き渡し、注文・取消報告、追跡、集計までを隔離環境で検証する。候補を使う前に実際の価格・在庫・配送条件と買い手の同意を確認する。
- 公開鍵を登録した販売業者の報告にEd25519署名を必須化した。隔離環境で検索、引き渡し、署名検証、注文・取消報告、買い手の追跡、再送を通しで検証した。次は外部注文台帳と契約済み仲介料の照合に必要な証拠を扱う。
- 12月2日の利用期間更新後に、無料枠、DB容量400 MB未満、物理作業領域、稼働条件を実測する。条件が整ったら、Worker、マイグレーション、必須テストがそろい、検証に成功した最新の安定コミットを特定して投入する。リリース番号やカレンダーだけで適否を決めず、投入したコミットと本番ヘルスの結果を記録する。
- 本番Supabase内のログ整理と完了後の通常VACUUMは [運用手順](../supabase/maintenance/IN_DATABASE.md) に沿って継続中。全DBの外部エクスポートは使用しない。非公開の本番数値や資格情報はこのファイルに記録しない。

## 統合開発の再開

- `tests/gpd33_worker.mjs` はMCP、公開API、x402、専門機能と販売業者一覧を検証する。`tests/gpd33_database.mjs` は隔離PostgreSQLで候補の検索から買い手認証、引き渡し、署名付き報告、取消、追跡、テスト台帳との照合までをつなぐ。`node tests/gpd33_reconcile.mjs` は入金・返金の照合を再検証する。
- 前回に続いて、[ロードマップの検証範囲](GPD_ROADMAP.md#統合検証の範囲と再開地点) とリリースCIを読む。買い手の経路は既存Authの確認が済むまで無効のまま。モック台帳を実績として扱わない。次の独立工程は外部台帳の安全な取込、一般商品とMerchantオファーの照合、販売業者接続・エージェント利用の観測。進められる工程を並行に処理し、テストを結合してから結果を記録する。

## 次の実装単位

1. **一件の実購買判断を収益までつなぐ。** 販売業者の受理から注文・取消までの試験データを使って通しで再現できるようにする。相手が同意した実案件で使えるテスト計画をまとめる。買い手の権限確認と販売業者の認証、照合に必要な参照、外部からの署名付き結果を整える。売り手の申告だけで商品取引成立や仲介収益を計上しない。
2. **取引と入金を照合する。** x402の情報提供料と商品代金・仲介手数料を区別し、成功、失敗、再送、取消、返金の検証を統合する。契約条件が確定している手数料だけを照合対象にする。決済記録と実収益の照合、および既存のMCP、API、x402と専門機能の回帰テストを同じ変更で確認する。
3. **購入可能な商品と利用者を増やす。** 全24カテゴリーで検証済み商品、在庫・配送オファー、必要な識別根拠の欠けを測定する。既存無料ソースとMerchantフィードを使い、地域、通貨、言語を明示した実取引の成功率で探索を改善する。公開OpenAPI、MCPの資料、互換性検証を先行し、エージェントの認知と導入を計測する。
4. **継続運用を自動化する。** 状態変化、データ品質、障害復旧、容量と転送量を検証し、取引量と収益の実績を探索配分へ反映する。無料枠内で利用可能な経路を優先する。

各実行で、関連する実装、テスト、修正、統合、検証を一つの流れで進める。部分実装を本番実証済みとしない。変更を保存するときは本ファイルとロードマップに、完了した工程、残る障害、次に検証する結果を追記する。外部契約、費用発生、実商品の注文、資金移動は権限と承認が確認された範囲でのみ行う。
